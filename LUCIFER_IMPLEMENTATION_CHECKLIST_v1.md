Items are grouped by how much they block, not by where they live in the spec. Every item links back to its spec section(s) and, where one exists, its `§12`/`§13` item number.

## Tier 1 — Architectural decisions with no mechanism yet — **RESOLVED (v0.18)**

All six closed in one pass. C1 and C2 got research deep dives (grounded in fresh precedent plus three clarifying answers about this deployment's actual shape); C3–C6 were narrower decisions needing no research.

- [x] **C1. Which isolation primitive backs the sandbox.** **Resolved:** Linux namespaces + `seccomp` (`bubblewrap`-style) — matching both OpenAI Codex CLI's and Claude Code's real sandboxing for this identical workload. Confirmed deployment shape (dedicated per-session hosts, not shared; Linux-only; overhead headroom available) removed the one reason to reach further, toward gVisor, so the two closest production analogues settled it. gVisor stays a documented upgrade path if hosting ever shifts to shared pools. Spec: §6.2, §7.4, §13 item 26 (resolved).

- [x] **C2. The triage heuristic.** **Resolved:** a fixed, operator-configured default starting model (`is_default_triage_model` on `ModelSpec`, §2) — not an automatic complexity classifier. Extends the same operator-declared philosophy just adopted for `ESCALATION_PATH` (v0.17); GitHub Copilot does run a real classifier here, but its mechanism isn't public, so there's nothing concrete to build from. Spec: §4.1, §4.2, §2, §13 item 8 (resolved).

- [x] **C3. Commit-race handling.** **Resolved:** the ref-level compare-and-swap fix (`git update-ref` with an expected-old-value check) is adopted outright, replacing the "plain `git commit`, not final" mechanism. No real tradeoff — a known-correct fix that had simply never been written in. Spec: §7.6, §12 item 1 (resolved).

- [x] **C4. Working-tree-level commit race.** **Resolved:** accepted as a documented, only-partially-mitigated limitation — no portable git tooling closes it. Same treatment as §9's ssh/https non-unification. Spec: §7.6, §12 item 2 (resolved).

- [x] **C5. `git push` blocklist gap.** **Resolved:** `push` added to `run_command`'s mutating-subcommand blocklist as defense-in-depth, independent of the restricted-network-mode question. Spec: §6.2, §12 item 8 (resolved).

- [x] **C6. `tool_call_reliability` field's fate.** **Resolved:** kept, as documentation-only — informational context for whoever composes `ESCALATION_PATH` by hand, read by no mechanism. Spec: §2, §12 item 14 (resolved).

New placeholders this pass introduced, folded into Tiers 3–4 below: which model actually gets the `is_default_triage_model` flag (C36), `bubblewrap`'s exact invocation (C37), and the ref path `update-ref` targets (C38).

## Tier 2 — Draft answer exists, needs confirming before it's load-bearing — **RESOLVED (v0.23)**

All five closed. Each was a safety- or correctness-relevant behavior that had rested on a proposal rather than a locked answer; C7–C10 were locked in one at a time (v0.19–v0.22), and C11 closes the tier.

- [x] **C7. Risk-flag trigger criteria.** **Resolved (v0.19):** four single-occurrence triggers — a `SENSITIVE_PATH_BLOCKED` hit, a CI/deploy-config or dependency-manifest edit, a secret-pattern match, and an unusually large/deletion-heavy diff (promoted to the primary criterion of the four, on real evidence rather than as an equal-weight guess). Grounded in Claude Code's real "Auto mode" classifier, which skips risk-checking ordinary in-repo edits because they're already reviewable via version control — reasoning that transfers directly here, since Lucifer's §7.5 review step already covers every diff unconditionally, making risk-flag's job earlier surfacing rather than a substitute safety net — and in an empirical study of 1,293 real agent-authored security PRs finding diff size a stronger rejection predictor than topic/keyword matching. Spec: §5.4, §13 item 11 (resolved). New placeholder introduced: real numeric size/deletion-ratio threshold, §13 item 55 — folded into Tier 3 below as C39.

- [x] **C8. Verification-suite command source.** **Resolved (v0.20):** explicit per-repo configuration only — the auto-detection fallback the draft originally leaned toward is dropped entirely, at your request. A repo with nothing configured skips the baseline capture and the whole verification gate (§3.4) rather than the harness guessing a command, and that skip is surfaced deterministically at diff-review time (§7.5) rather than silently treated as a pass. Grounded in four real data points: Aider (`--test-cmd`, no fallback) and SWE-bench's harness (explicit per-repo command registry) both require configuration with no heuristic option at all; GitHub Copilot's own docs admit its fallback (trial-and-error dependency/build discovery) is "slow and unreliable... and in some cases... completely unable" to work; Claude Code has no automatic verification by default whatsoever unless a human wires one up. Spec: §3.4, §3.5, §13 item 7 (resolved).

- [x] **C9. Find/replace ambiguity handling.** **Resolved (v0.21):** `EditBlock` gains a `replace_all: bool = False` field. Left at default, a multi-match `find` still fails with `FIND_BLOCK_AMBIGUOUS`, unchanged from every earlier draft — no mode where the tool picks an occurrence on the model's behalf. Setting it `true` makes a multi-match expected rather than an error, replacing every occurrence in that block's scope, without disturbing §6.1's existing sequential/atomic multi-block mechanics. An occurrence-index alternative was declined outright: no real precedent for it was found anywhere researched, and a positional index is fragile against this spec's own sequential-blocks semantics (an earlier block in the same call can shift what a given index would even point at). Grounded in Claude Code's own multi-edit tool, which carries exactly this `replace_all: bool` field, confirmed via a live GitHub issue (#3337) showing its actual unset-default error message. Spec: §6.1, §13 item 14 (resolved in full).

- [x] **C10. Verification target-confirmation.** **Resolved (v0.22):** accepted outright as a permanent v0 limitation rather than left open. Verification (§3.4/§3.5) checks for new regressions only; it never confirms the task's actual target was fixed. SWE-bench's `FAIL_TO_PASS`/`PASS_TO_PASS` test split is the one real mechanism found that mechanically answers this question, but it depends on a human having already curated, per-task, which test(s) are expected to flip — foreknowledge unavailable to a general agent at runtime, so it doesn't transfer as a buildable mechanism here. Neither Claude Code nor GitHub Copilot's coding agent closes this gap either; both rely on human diff review for the same judgment, the role Lucifer's own §7.5 review step already plays. Spec: §3.5, §12 item 3 (resolved).

- [x] **C11. Workspace's staged-but-uncommitted content on a true abort.** **Resolved (v0.23):** the session-snapshot directory (§7.7) that already exists to support resume is not purged on a true, unresumable abort — no explicit delete step is added to the abort path, so the staged diff simply survives on disk for a human to inspect or manually recover, distinct from (and not reconstructed by) the resume mechanism that reads the same directory. This sits alongside, not instead of, the wind-down step's forced model-authored narrative (§5.5) — a post-mortem reviewer gets both the narrative and the real staged content. Grounded in a real Cursor forum bug report describing its agent silently wiping 45 files of uncommitted work via `git stash` plus a hard reset with no warning; the lesson — uncommitted work must never become unrecoverable without deliberate, visible human intent — applies directly, since aborting a session is the human ending the session, not asking for its work to be discarded. Disk-retention policy for accumulated aborted-session directories is named as a separate, later housekeeping decision. Spec: §7.7, §12 item 9 (resolved).
