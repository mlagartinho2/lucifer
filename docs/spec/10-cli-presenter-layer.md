## 10. CLI / Presenter Layer

The CLI only replaces the presenter — diff display, `ask_user` interaction, streaming output. The router, Workspace, loop, tool schema, and retrieval pipeline are all unchanged by which presenter sits on top; a future IDE plugin would swap this same presenter role without touching anything else in this spec.

**Resolved (v0.26, Tier-4 checklist C27 — closes §13 item 24):** both, not a single-shot-vs-REPL choice — the two serve genuinely different use cases rather than competing for the same one. `lucifer` with no arguments opens an interactive session: a persistent, turn-by-turn experience where a human gives a task, watches the trajectory work, and can follow up immediately without restarting the process. A separate, explicit non-interactive invocation (naming not finalized here — `lucifer run "<task>"` or a Codex-CLI-style `lucifer exec "<task>"` subcommand are both reasonable) runs a single task to completion autonomously and exits, printing a final result rather than holding a session open — for CI pipelines, pre-commit/pre-merge hooks, scheduled batch jobs, or being invoked by another program. Interactive is the default surface, matching every real precedent researched; non-interactive is the explicit opt-in.

This is one of the few places in this draft where every real precedent researched converged on the identical shape, rather than needing to be weighed against a competing design. Claude Code, GitHub Copilot CLI, and OpenAI Codex CLI all ship exactly this pairing: an interactive session as the bare-invocation default, plus a distinct non-interactive flag or subcommand for automation (Claude Code's `-p`/`--print`, explicitly documented as "the CLI face of the Agent SDK... for scripts and CI/CD," with worked examples wired into `package.json` scripts and GitHub Actions; Copilot CLI's `-p`, described in GitHub's own docs as for "quick, one-shot prompts... plugging Copilot into automated workflows"; Codex CLI's `codex exec`, documented for "CI, pre-merge checks, scheduled jobs"). The reasoning is consistent across every source: interactive suits a human exploring and iterating turn by turn; non-interactive suits anything needing a deterministic run-and-exit invocation, which is also why several of these tools (Claude Code, Codex CLI) add structured JSON output specifically for the scripted path. A real cautionary data point reinforces building both from the start rather than deferring one: Aider originally shipped REPL-only, and a live GitHub issue against it is a direct feature request from a user whose scripted use broke because of it ("aider asks in interactive way") — non-interactive support (`--message`, `--yes`) was retrofitted afterward, reactively. No current mainstream coding-agent CLI researched ships single-shot-only either. This pairing also fits Lucifer's own architecture cleanly: the staged/reviewed workflow (§7.5) already means a non-interactive CI run can complete its work and leave a diff staged for separate human review, rather than needing to be interactive to be safe.

**Widened (v0.69, Tier-4 checklist C55 — §6.6):** both invocation modes gain an optional `--agent <name>` flag, pinning a custom agent's persona for the whole trajectory (§6.6's persona-select mode) — the same real flag GitHub Copilot CLI itself ships. Nothing about the interactive/non-interactive split above changes; the flag composes with either, though nested dispatch (§6.6's other mode) is only reachable once a trajectory is already running a reactive loop, which the non-interactive invocation still does internally even though it prints only a final result.
